🕷️ Crawl — Finds fresh postings

Stage 1 of 4 · JavaScript module · reads and writes Supabase

Input → Output

Input: the search term “software engineer” against Remotive’s public jobs API (20 results per call). Output: a live count of current listings plus the first three — title @ company — written to Supabase as a run row.

How it works

GET https://remotive.com/api/remote-jobs
  ?search=software%20engineer&limit=20

count = data.jobs.length
sample = jobs.slice(0, 3)  // “title @ company”

When it fails

If Remotive is unreachable, returns a non-200 status, or the JSON has no jobs array, the run fails and is logged as failed — the other workflows still run.

02 · The pipeline

      
Four small jobs, one reliable chain

      
Each stage does one thing, writes its result to Supabase, and hands off. If a stage fails, the chain logs the failure and moves on — the next day’s cron run picks it up again.

Under the hood

      
Small, honest, observable

      

        
JavaScriptPipeline, modules and dashboard — one script, no framework.

        
SupabaseWorkflow runs and counts, read and written over REST.

        
CronDaily 05:00 PT — /api/cron runs one randomly chosen workflow.

        
Run logEvery run, manual or scheduled, logged with status and duration.

        
TimeoutsExternal calls are capped (6 s crawl, 5 s per lead) so a slow site can’t hang a run.
